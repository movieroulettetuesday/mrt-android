# Backend options for polls and shared ratings on Android (and iOS)

_2026-10-21 (ET). Decision doc only. No backend has been built. Free-tier numbers come from the vendors' pages as of today._

**What iOS does today:** anonymous records in the CloudKit **public** database of `iCloud.com.movieroulettetuesday.app`: `PollVote {pollId, option}`, `ListenerRating {movieId, stars, halfStars}`, and create-only `Suggestion`. Anyone can read results (`_world` READ). Writing needs a signed-in iCloud user, and the record name is `vote-<pollId>-<sha256(iCloudUserID+pollId)>`, so a re-vote overwrites the old one. Results are counted on the device. Hosting cost is $0. Android has no CloudKit SDK and most Android users have no Apple ID.

## Recommendation
**Option A: keep CloudKit as the single source of truth.** Android reads results directly with a CloudKit API token and writes votes and ratings through a tiny Cloudflare Worker that holds a CloudKit server-to-server key. iOS doesn't change, there is one shared pool of votes, hosting stays at $0 on free tiers, and no new vendor holds user data. Until Matthew approves and the keys exist, **ship Android 1.0 with F**: read-only display (optionally with option A's reads), mailto suggestions, personal ratings on the device, and the vote/rate buttons hidden. Choose **B** only if Matthew wants to move off CloudKit on both platforms. Open items for Matthew: OK to create a CloudKit API token and S2S key and a Cloudflare account; approve the install-ID approach and the privacy-policy wording; decide whether Android can also create `Suggestion` records through the relay or stays on mailto.
